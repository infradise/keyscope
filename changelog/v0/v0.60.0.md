# Changelog

## v0.60.0

This release introduces the **Local Container Playground** directly into the primary activity bar, bringing seamless local container lifecycle management to Keyscope. For environments without an existing container runtime (such as Docker Desktop or Rancher Desktop), Keyscope v0.60.0 also debuts an on-demand **Built-in Isolated Container Engine (BICE)** alongside quick workspace switching via the new **System Tray** integration.

### Added

- **Local Container Playground**:
  - Added a dedicated container management workspace to the global activity bar.
  - **Image & Container Lifecycle**: Pull images with real-time, per-layer download and extraction progress bars (including quick-select presets for `redis:latest`, `valkey/valkey:8.0`, and `valkey/valkey:9.0`), run containers with custom port mappings (`Host:Container`) and environment variables, and stop or remove containers effortlessly.
  - **Live Telemetry & Resource Monitoring**: Real-time monitoring of host and per-container CPU usage, RAM consumption, Disk R/W, and Network RX/TX throughput.
  - **Inspection & Configuration**: Edit and save container configurations on the fly (`Overview & Edit` for Container Name, Restart Policy, Memory Limit, and CPU Shares), stream real-time container output (`Live Logs`), and inspect full container metadata via the built-in JSON viewer (`Raw Inspect (JSON)`).
  - **Flexible Socket & Connection Management**: Automatically detects standard local sockets (e.g., `/var/run/docker.sock`) with support for custom socket path and connection editing.

- **One-Click "Open in Data GUI" Bridge**:
  - Automatically detects supported data store containers (such as Redis and Valkey) as soon as they reach the `Running` state and activates the **+ Open in Data GUI** action button.
  - Clicking **+ Open in Data GUI** registers the container as a new connection in the Standalone Data Stack and switches directly to the Data GUI in 0.1 seconds—eliminating manual host/port configuration or external CLI tools.

- **Built-in Isolated Container Engine (BICE)**:
  - An on-demand, zero-conflict fallback container runtime designed for users without Docker Desktop installed—or developers who want a clean, isolated sandbox that never touches host `/var/run/docker.sock` configurations.
  - **One-Click Provisioning**: Downloads a lightweight, platform-native runtime bundle (approx. 50 MB–150 MB across Linux, macOS, and Windows for both `x86_64` and `arm64`), extracts the runtime filesystem, provisions a 64 GB persistent sparse virtual disk, and verifies the isolated socket in seconds.
  - **Instant Clean Reset**: Includes a **Reset Engine** capability that stops the built-in daemon and wipes its virtual disk and runtime files, allowing developers to restore a clean sandbox state at any time.

- **System Tray Integration**:
  - Added system tray support for instant access and navigation across **Keyscope**, **Kubernetes**, **Data Stack**, and **Local Container Playground**.
  - Displays a live list of currently running containers (e.g., active Redis and Valkey instances) directly in the tray menu for rapid workspace and context switching.

### Runtime & Engine Specifications
- **Built-in Isolated Container Engine (BICE)**: Moby / Docker Engine `29.4.3` compatible runtime (API `1.54`) on Alpine Linux `3.20.3` minimal rootfs (`linux/amd64`, `linux/arm64`).
